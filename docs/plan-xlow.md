# ОБНОВЛЕНИЕ (выполнено 06.09.2026) — исходный план НЕ актуален в целом виде

## Ключевое открытие
Маппинг effort → инструкция для Qwen3.8 живёт **не в Jinja-шаблоне GGUF, а в Go-renderer'е**:
- `model/renderers/qwen35.go` — структура `Qwen35Renderer` с вариантами: `qwen3.5` (default) и `qwen3.8` (`newQwen38Renderer()`).
- Функция `qwen38ReasoningInstructions(think *api.ThinkValue)` инжектит текст в system по уровню:
  - nil/unset → xhigh-текст ("think carefully…")
  - "low" → "Keep your thinking brief and focused…"
  - "medium" → пусто
  - "high"/"max" → полный xhigh-текст
- Вызывается на Go-сервере (`server/prompt.go:138`) ДО отправки в llama-server. Jinja/GGUF для этого пути не нужен.
- Вторичный путь `chat_template_kwargs.reasoning_effort` (llama_server.go ~2150–2280) тоже сериализуется, но основной — Go-renderer.

## Что реально сделано
1. Найдено: у orchestrator в конфиге стоял `renderer: qwen3.5` → без маппинга effort.
2. Новый Modelfile (`/tmp/Modfile_orchestrator_v2`): те же два FROM-blob (GGUF 12ГБ + второй файл 889МБ) + **`RENDERER qwen3.8`** (parser оставлен `qwen3.5`).
3. Создана и проверена `orchestrator:v2`, промоутится в `orchestrator:latest`. В конфиге теперь `renderer=qwen3.8`.
4. Проверка API: `/think low|high` меняют инструкцию; модель отвечает, thinking-блок присутствует (разница длины при temp=1 шумная — это ожидаемо).
